# Lua interpreter benchmarks

Small, self-contained Lua 5.4 programs for comparing Dodo's Lua interpreter
(`std/script/lua`, driven by `examples/lua`) against the reference PUC Lua
5.4.9 interpreter. Every benchmark is an original implementation, takes no
command-line arguments, and has a size constant at the top of the file. The
sizes are tuned so that each one takes roughly 0.5-2 s under the reference
interpreter on a recent machine.

Each benchmark prints a short deterministic checksum (1-3 lines). The harness
compares that output between the two interpreters, so a fast but wrong
interpreter shows up as a mismatch, not as a win. Floating-point results that
go through libm (`math.sin`, `math.exp`, ...) are printed with `%.6f` so that
last-bit differences between libm implementations do not matter. Benchmarks
that use only `+ - * /` and `math.sqrt` (all correctly rounded in IEEE 754)
print with more digits.

## Benchmarks

| file | what it stresses |
|---|---|
| `fib.lua` | Recursive Fibonacci: Lua-to-Lua calls, returns, integer arithmetic and comparison. |
| `binary_trees.lua` | Allocating and walking many short-lived binary trees plus one long-lived tree: table allocation and the garbage collector. |
| `nbody.lua` | Simulating the Jovian planets: float arithmetic, field reads and writes on small tables, `math.sqrt`. |
| `spectral_norm.lua` | Power iteration on an implicit matrix: nested numeric `for` loops, array indexing, float division, small function calls. |
| `fannkuch.lua` | fannkuch-redux over all permutations of 1..10: small integer arrays, swaps, tight `while` loops. |
| `mandelbrot.lua` | Mandelbrot set on a 1600x1600 grid, printed as a checksum: float multiply/add inner loop, integer bit operations. |
| `string_concat.lua` | String building: `..` in loops, multi-operand concatenation, `table.concat`, `string.rep`, number-to-string conversion, short string interning, GC of strings. |
| `string_format.lua` | `string.format` (`%d %s %x %-5s %05d`), `string.find` (plain and pattern), `string.match` captures, `gsub` with table/function/string replacements, `gmatch`. |
| `table_ops.lua` | `table.insert`/`table.remove` at the ends and in the middle, `table.sort` with the default comparator and with Lua comparison functions, `table.move`, `table.unpack`, `table.concat`, `#`. |
| `closures.lua` | Creating closures in loops, calling them through tables, reading and writing shared upvalues, upvalues closed at the end of each loop iteration, nested upvalue access. |
| `oop_methods.lua` | Method calls (`obj:method()`) resolved through a three-level `__index` chain, super calls, polymorphic dispatch, field writes. |
| `coroutine_ring.lua` | A ring of 503 coroutines passing a token, a `coroutine.wrap` generator pipeline, many short-lived coroutines: resume/yield cost and value passing. |
| `word_freq.lua` | Word frequencies over pseudo-random text generated by an LCG: string keys in hash tables, `gmatch` tokenizing, table growth, sorting with a comparator. |
| `float_math.lua` | Simpson integration with `math.sin`/`math.exp`/`math.sqrt`, a 240x240 dense matrix multiply, Newton iteration: float-heavy code with library calls. |

## Running

Build the reference interpreter once (downloads and verifies PUC Lua 5.4.9
into `target/lua-reference`):

```sh
python3 scripts/test_lua.py fetch
```

Build our interpreter with optimizations (benchmarking a debug or `-O 0`
build is not meaningful):

```sh
target/debug/dodo build examples/lua -O 2 -o build/lua
```

Run the benchmarks:

```sh
python3 scripts/test_lua.py bench                       # all benchmarks, build/lua vs reference, best of 3
python3 scripts/test_lua.py bench --repeat 5            # best of 5 runs
python3 scripts/test_lua.py bench --lua build/lua fib nbody   # selected benchmarks (names or name prefixes)
python3 scripts/test_lua.py bench --lua ref --repeat 1  # reference vs itself: sanity check of the setup
```

`--lua` selects the interpreter under test (default `build/lua`; the literal
value `ref` means the reference build). Each benchmark runs with
`benchmarks/lua` as the working directory.

## Output

Progress lines go to stderr. The result on stdout is a markdown table with
the best-of-N wall-clock time for each interpreter and the ratio
(our time / reference time; lower is better), followed by the geometric mean
of the ratios:

```
| benchmark | PUC Lua 5.4.9 (s) | lua (s) | ratio |
|---|---:|---:|---:|
| fib | 1.040 | ... | ...x |
...
| **geometric mean** | | | **...x** |
```

If a benchmark's output differs between the two interpreters, or if one of
them exits with an error, the row is marked `(output differs)`, both outputs
are printed below the table, and the command exits with status 1. A failed
run is reported as `failed` in the time column.

## Adding a benchmark

Put a new `name.lua` in this directory. Keep it deterministic: no timings,
no `os.time`/`os.clock`/`math.random` in the output, no table addresses, no
unsorted `pairs` order, no full-precision prints of libm results. Use an
integer LCG if you need pseudo-random data (take the high bits; the low bits
of a power-of-two-modulus LCG have short periods). Size it with a constant at
the top so that it runs for about 0.5-2 s under the reference interpreter.
